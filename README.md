# World Economic Data Pipeline

A Python ETL pipeline that extracts historical GDP data by country, cleans and validates the dataset, stores processed records in CSV files, and loads valid data into a normalized SQLite database.

The project was built as a hands-on Data Engineering exercise focused on ETL design, data quality, relational databases, SQL constraints, logging, and automated testing.

## Pipeline Overview

The pipeline follows the following process:

```text
Historical GDP Web Source
        ↓
      Extract
        ↓
     Transform
        ↓
Data Quality Validation
        ↓
 ┌───────────────┐
 │ Valid Records │
 │ Rejected Data │
 │ Duplicates    │
 └───────────────┘
        ↓
      SQLite
        ↓
   SQL JOIN Query
```

## Features

- Extracts historical country GDP data from an archived Wikipedia page.
- Parses HTML using BeautifulSoup.
- Cleans GDP values and converts them to numeric types.
- Extracts and validates four-digit year values.
- Detects missing required fields.
- Separates invalid records into a rejected dataset.
- Detects duplicate country/year combinations.
- Saves valid, rejected, and duplicate records as separate CSV files.
- Creates a normalized SQLite database.
- Uses primary keys, foreign keys, unique constraints, and NOT NULL constraints.
- Prevents duplicate database records using `INSERT OR IGNORE`.
- Executes SQL JOIN queries across related tables.
- Logs important ETL events and errors.
- Includes automated tests for transformation and database behavior.

## Database Design

The SQLite database contains two related tables.

### `countries`

| Column | Description |
|---|---|
| `country_id` | Auto-generated primary key |
| `country_name` | Unique country name |

### `gdp_records`

| Column | Description |
|---|---|
| `record_id` | Auto-generated primary key |
| `country_id` | Foreign key referencing `countries` |
| `year` | GDP record year |
| `gdp_usd_million` | GDP value in millions of USD |

The combination of `country_id` and `year` is unique, preventing multiple GDP records for the same country and year.

## Data Quality Process

During transformation, records are separated according to their quality.

### Valid records

Rows containing valid values for:

- Country
- GDP
- Year

are retained for database loading.

### Rejected records

Rows containing missing or invalid required values are stored separately in:

```text
data/rejected_gdp.csv
```

### Duplicate records

Duplicate country/year combinations are stored in:

```text
data/duplicated_country.csv
```

while only the first valid occurrence is retained for loading.

## Running the Pipeline

Install the required dependencies:

```bash
pip install -r requirements.txt
```

Run the ETL pipeline:

```bash
python3 main.py
```

The pipeline will:

1. Extract the source data.
2. Validate and transform the records.
3. Generate CSV outputs.
4. Create the SQLite database.
5. Load valid records.
6. Execute a query showing the ten highest GDP values.

## Running the Tests

From the project root directory:

```bash
python3 -m tests.test_pipeline
```

The test suite verifies:

- Basic data transformation
- Missing-value rejection
- Empty-string rejection
- Validation before duplicate detection
- Database creation and loading
- Duplicate insert prevention
- Foreign-key enforcement
- Multiple years for the same country
- Correct JOIN results
- Correct query ordering and returned results

The test database is created temporarily and removed after the test run.

## External Data Source

The extraction step uses a historical snapshot hosted by the Internet Archive's Wayback Machine.

Because this is an external service, the source may occasionally return HTTP errors such as:

```text
429 Too Many Requests
```

This is an external rate-limit response and does not indicate a failure in the transformation or database logic.

HTTP extraction failures are logged by the pipeline.
